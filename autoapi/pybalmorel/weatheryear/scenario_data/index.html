pybalmorel.weatheryear.scenario_data

Weather-Year Scenario Data

Turns WEATHERYEAR’s CapDev output for one year into the .inc files a Balmorel scenario’s data/ folder needs. Balmorel’s bb4datainc.inc only reads a scenario’s own data/<NAME>.inc when the filename matches exactly, and some WEATHERYEAR output has a different name, is split across several files, or holds scaling factors rather than values. Each rule below was verified against Balmorel’s override mechanism in the GREAT project (mbrpdoc-great/scripts/preprocessing/clean_weather_year_inputs.py, its ADRs 0015, 0021, 0022, 0034 and 0036), where this logic comes from.

  • Wind and solar profiles and FLH keep their names. Wind gets one fallback line per existing area CorRES has no profile for, and its catch-all borrows a wind area instead of DK2_NoDH.

  • Hydro files lose WEATHERYEAR’s _WY suffix. The FLH files are scaling factors, so the base values load first (under $onMulti) and are multiplied. The hydro profiles get base’s catch-all for areas without a weather-year profile.

  • Demand is split by user in WEATHERYEAR but read as one DE_VAR_T.inc and one DH_VAR_T.inc. Each loads the base default first, since the weather year only sets its own users’ cells.

  • Individual-user heat (INDIVUSERS_DH*.inc) assigns straight into DH and DH_VAR_T, so it is loaded inside DH.inc and DH_VAR_T.inc, and the addon’s own override files are written empty so it isn’t applied twice.

  • Top-level to_balmorel/*.inc files are copied, except GKFX_renewable.inc (the existing fleet comes from base) and SUBTECHGROUPKPOT.inc.

  • Heat-pump COP files are not written; models that use them need their own wrapper.

pybalmorel.weatheryear.scenario_data.write_scenario_data(capdev_dir: str | pathlib.Path, to_balmorel_dir: str | pathlib.Path, dest_dir: str | pathlib.Path, base_data_dir: str = '../../base/data', drop_areas: tuple[str, ...] = ()) → list[pathlib.Path]

Write one weather year’s Balmorel scenario data files.

Args:
capdev_dir (str | Path): A CapDev variant folder from WEATHERYEAR, e.g.

‘<output>/<year>/to_balmorel/CapDev/raw’ for the actual weather.

to_balmorel_dir (str | Path): The ‘<output>/<year>/to_balmorel’ folder,

whose top-level .inc files are copied too.

dest_dir (str | Path): The scenario’s data/ folder. Created if needed;

existing files with the same names are overwritten.

base_data_dir (str, optional): GAMS path, relative to the scenario’s

model/ folder, of the base data the weather year is applied on top of. Defaults to ‘../../base/data’.

drop_areas (tuple[str, …], optional): Areas the model doesn’t have,

removed wherever they appear (matched as substrings). Defaults to ().

Raises:

FileNotFoundError: If capdev_dir doesn’t exist.

Returns:

list[Path]: The files written.
