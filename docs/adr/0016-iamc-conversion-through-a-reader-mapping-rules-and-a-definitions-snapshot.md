# Convert to IAMC through a reader, Mapping Rules as data, and a bundled Definitions Snapshot

The IAMC converter matches two vocabularies, and both change without
warning. The common definitions
(`github.com/IAMconsortium/common-definitions`) are a live repository with
no releases or tags; variables are added and renamed between commits.
MainResults change from study to study: `2027_rosendal` added
`DR_FLEX_YCRAST`, V2G symbols and `BIOMETH_PRICE_YST`; heat transmission
(`XH_FLOW_YCA`) appears in some studies and not others; industry areas are
`IND-LT` in some and `IND-LT-DH` / `IND-LT-NODH` in others. A converter
that matched the two in code would break quietly on either side, and every
fix would need a release.

The converter therefore has three layers, each owning one side of a change:

1. **Reader.** The only code that knows Balmorel symbol and column names.
   It reads MainResults into one long table of what each unit does:
   scenario, year, country, area (and receiving area, for transmission),
   unit (`G`), technology type, fuel, commodity, demand category, quantity
   kind (capacity, output, demand, exchange, …), value. Symbols only some
   results have are read where they exist. Technology types, fuels and commodities it doesn't
   know pass through to the rules, which send them to Other with a warning.
2. **Mapping Rules.** CSV tables shipped in the package, keyed on
   technology type, fuel and commodity, with an optional unit-name pattern
   for what only names carry (CCS). They map each row of the long table to
   segments of IAMC Variable names, to `-` (not reported, e.g. storage) or
   to `import` (Import Units), and fuels to Fuel Categories. Further
   tables tell area kinds apart by name pattern, say which demand
   categories are final demand, and pick the IAMC stem per quantity,
   commodity and area kind. Rows the caller passes take precedence over the
   shipped ones. Quantities that need arithmetic across rows stay in code:
   Heat Exchange netting and tracing, Net Exports, the Commodity Balance,
   the Output-Share Split, Net CO2 Emissions, On-Site Use, and parent
   sums.
3. **Definitions Snapshot.** `src/pybalmorel/iamc/definitions/` holds
   `variables.csv` (variable, unit, description, tier), `regions.csv`
   (country names and ISO3 codes) and `SOURCE` (commit hash and date),
   generated by `dev/update_iamc_definitions.py` from a pinned commit of
   common-definitions, with
   `nomenclature-iamc` (a dev-only dependency) expanding the `{Tag}`
   placeholders. Every rule target and every output name is checked
   against it, and values are converted to its units. Callers can pass
   their own definitions in the same format. Nothing is fetched at runtime.

The Template (e.g. NMSF Study 2's `varlist.xlsx`) is not shipped. Callers
pass it to limit the output to the names their intercomparison accepts.

## Considered options

- **`nomenclature-iamc` at runtime**, reading a local clone or fetching the
  repository. Rejected: it brings pyam into pybalmorel's dependencies,
  needs network access or a clone, and the output would depend on whichever
  commit the user happens to have.
- **The Template as the source of names.** Rejected: it is one
  intercomparison's subset, so anything outside it could not be reported,
  and the next intercomparison would bring a different list.
- **Mapping in code** (dicts in a module, like `formatting.py`). Rejected:
  a new technology type or a renamed variable would need a code change and
  a release, and a study could not override a classification.
- **Rules keyed on unit names (`G`).** Rejected: thousands of names that
  differ by study, while technology type and fuel already come from each
  unit's own data. Unit-name patterns are kept only for what names alone
  carry.

## Consequences

- Moving to newer common definitions is deliberate: run the dev script,
  review the diff of `variables.csv`, then fix the rule rows that a
  GAMS-free test lists as targeting names no longer in the snapshot.
- A new Balmorel technology type, fuel or symbol lands in Other with a
  warning that names it, until a rule row is added. A GAMS-dependent test
  on `examples/files` fails on categories no rule covers, so the repo
  catches it before a user does.
- The quantities computed in code still change with Balmorel: a renamed
  symbol behind the Output-Share Split or Net CO2 Emissions needs a code
  change in the reader.
- Energy a result file makes or uses outside the symbols read (heat
  transmission it doesn't list, OptiFlow's heat) can't be reported. The
  Commodity Balance names the regions where it happens rather than letting
  Secondary and Final Energy disagree silently. It also catches a demand
  category the rules lack: hydrogen in three studies didn't add up until
  OptiFlow's `ENDO_OPTIFLOW` got a rule row.
- pybalmorel ships a copy of CC0 data, and `SOURCE` records the commit.
  common-definitions defines no countries itself, so the country names come
  from nomenclature's country list, which projects reporting by country
  switch on with `country: true` (the Template's Region sheet lists the
  same names). Balmorel countries reach them through ISO3 codes in a rule
  table, so a renamed country needs no rule change.
